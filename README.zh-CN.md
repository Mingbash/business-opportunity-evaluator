# 商业机会评估器 · Business Opportunity Evaluator

**手头的时间和钱，值不值得拿来试这个生意？**

把你想卖什么、打算卖给谁、能投入多少告诉 Agent。它会看买家现在怎么解决问题，也会跟着你从找客户算到回款。最后给出一份简短判断，写清哪些有依据、哪些还靠猜，以及下一步先验证什么。

[English](README.md) · [看一份完整示例](examples/local-service.zh-CN.md) · [快速开始](docs/QUICKSTART.zh-CN.md)

## 拿一个正在犹豫的点子试试

在 Codex 安装这个 skill。

```sh
npx skills add Mingbash/business-opportunity-evaluator --skill business-opportunity-evaluator -a codex
```

开一个新对话，说说你的想法。比如：

> 用 `$business-opportunity-evaluator` 帮我看看，周末在镇上做自行车上门取送维修怎么样。我每周能拿出六小时，还不知道有人愿不愿意为取送付钱。

你会收到一份简评和下一步建议。拿这个例子来说，可以先问车主愿意付多少取送费，再算跑一趟还剩多少时间修车。需要往下查，可以接着请它做一份附来源的详细评估。

也可以从 [Releases](https://github.com/Mingbash/business-opportunity-evaluator/releases) 下载单项包，把整个目录复制到 Agent 的 skill 目录。手动安装不用 Node.js。[查看安装步骤和适用环境。](docs/QUICKSTART.zh-CN.md)

## 它会帮你算哪些账

先定清楚一项服务和一类买家，再顺着实际流程看：买家去哪儿找、现在用什么替代、你要花多少时间才能做完交付并收到钱。最后分别给市场、你现在的入场条件和整体机会一个判断。

评估有八个维度，权重可以按目标调整。周末补贴收入和靠它养团队，看重的东西会不一样。S–F 等级用来概括眼下的判断。还没查到的事会留在报告里，仅凭手头笔记做出的结论也会标成暂定。

## 我为什么做这个 skill

之前比较 AI 服务和数字产品时，我常常卡在同一段路上：东西可以做出来，第一单要怎么来？当时有三句原话，后来都变成了评估规则。

> “我觉得你又忽略了获客门槛/市场新玩家进入友好度的维度”——2026-09-24

所以要单独看获客。能列出一张潜在客户名单只是起点，还得知道怎么找到愿意回你、愿意付钱的人。

> “商业不是一门科学，无法在真正执行获得市场反馈前通过研究和推导得到100%置信度的结论”——2026-09-25

所以报告要落到一个可以去验证的动作。比如，如果取送费决定这单赚不赚钱，就先拿着报价去问车主，再考虑做预约网站。

> “主业类和副业类的评估rubric要有区分”——2026-09-26

于是同一项按单交付的服务可以放在两个目标下看。周末赚一点现金也许合适，要靠它养团队就得重新算每单工时。

## 用你手头的材料开始

分析用你说话的语言，市场范围按业务实际覆盖的地方来定。默认在对话里给 Markdown。想并排比较几个点子时，可以要 CSV 或工作簿。第一次试用，给一段话就够了。
