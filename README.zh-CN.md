# 商业点子验证 · Idea Validation

**按你手里的资源和想达到的目标，这门生意值得试吗？**

把你想试什么、手头有什么告诉 Agent。「靠做网站赚钱」这样的想法，可以拆成几门不同的生意。它会分别看谁付钱、客户从哪来、你要做多少才能收到钱。已经想好了卖给谁、交付什么，就从你给的方案开始。

[English](README.md) · [看网站评估案例](examples/website-paths.zh-CN.md) · [快速开始](docs/QUICKSTART.zh-CN.md)

## 拿一个正在犹豫的点子试试

在 Codex 安装这个 skill。

```sh
npx skills add Mingbash/business-opportunity-evaluator --skill idea-validation -a codex
```

仓库地址保持不变，旧的 `--skill business-opportunity-evaluator` 安装命令继续可用，评估规则相同。新旧名称选一个安装即可。

开一个新对话，说说你的想法。比如：

> 用 `$idea-validation` 帮我看看，周末在镇上做自行车上门取送维修怎么样。我每周能拿出六小时，还不知道有人愿不愿意为取送付钱。

你会收到一份八项简评。市场怎么样、你现在进不进得去、整体值不值得试，会分别给评级。自行车这个例子里，可以先算跑一趟取送的时间，再问车主愿意为取送付多少钱。

如果你只说了一个大方向，它会先拆出最多三条值得比较的路径。每条都会写明谁付钱、交付什么、怎么收费、去哪里找买家，然后说明先验证哪条，以及什么新证据会改变这个顺序。

历史版本仍使用 `business-opportunity-evaluator` 名称和调用方式。可以从 [Releases](https://github.com/Mingbash/business-opportunity-evaluator/releases) 下载单项包，把整个目录复制到 Agent 的 skill 目录。手动安装不用 Node.js。[查看安装步骤和适用环境。](docs/QUICKSTART.zh-CN.md)

## 它会帮你算哪些账

2026 年 9 月 26 日，我把「卖网站模板」当作副业研究过。当时比较的是这三条路。

| 路径 | 谁付钱，买什么 | 当时怎么决定 |
|---|---|---|
| 通用网站模板 | 个人和小商家买现成网站版式 | 先放弃。免费和低价版式已经覆盖了不少需求。 |
| 给小代理做垂直 Framer 包 | 小型代理和自由设计师买站点、可复用组件、内容样例和交接材料 | 优先小额测试。挑一类代理常做的项目，看看是否有人为复用付钱。 |
| 婚礼化妆师预约站模板 | 独立化妆师和小工作室买作品展示、询盘和预约流程 | 先做预览。给十位化妆师看，有两笔预购再做完整版。 |

这些是当时的研究判断。[看完整历史案例。](examples/website-paths.zh-CN.md)

**默认简评**先写清业务定义、评估日期、地区、买家和目标，再给八项判断。每项有分数或「未知」，并说明依据。

1. 付费需求和能服务的市场
2. 竞品和客户现有替代方案
3. 怎么找到买家
4. 入场门槛和距离首笔回款有多远
5. 做一单要花多少、能留下多少
6. 交付什么、给客户解决什么问题
7. 收入和工作能不能重复
8. 为什么是现在、什么变化会让机会失效

最后给市场、当前入场和整体机会三项评级，各自带置信度。建议会写到先做什么、最影响决策的未知是什么，以及什么情况下该停。

**完整分析**多给五组字段。决策总览写首选路径和改变判断的条件。机会详情写买家、替代、获客和交付。评分表给出权重和门槛。证据台账说明每条材料支持什么。假设与情景单独列出价格、销量、工时等变量。[看完整字段。](skills/idea-validation/references/full-schema.md)

## 直接问 AI「2026 年做什么生意赚钱」为什么经常问不到点上

早期有次 AI 建议去「服务市场」找客户。我回了一句：「你说一句服务市场没法解决我的问题。」我想知道真实项目在哪发，怎么判断这些人真有需求，以及没案例时第一单怎么谈下来。

「卖网站模板」也停在同一层。拆开看，代理买的是能在下一个项目里继续用的交付包，婚礼化妆师买的是能从作品展示走到询盘和预约的站点。两个买家得分别去找，给他们看的样品也不同。弄清这些，才能决定第一步是找代理看复用包，还是拿预约流程去问化妆师。

## 我为什么做这个 skill

之前比较 AI 服务和数字产品时，我常常卡在同一段路上：东西可以做出来，第一单要怎么来？当时有三句原话，后来都变成了评估规则。

> “我觉得你又忽略了获客门槛/市场新玩家进入友好度的维度”——2026-09-24

所以要单独看获客。能列出一张潜在客户名单只是起点，还得知道怎么找到愿意回你、愿意付钱的人。

> “商业不是一门科学，无法在真正执行获得市场反馈前通过研究和推导得到100%置信度的结论”——2026-09-25

所以报告要落到一个可以去验证的动作。比如，如果取送费决定这单赚不赚钱，就先拿着报价去问车主，再考虑做预约网站。

> “主业类和副业类的评估rubric要有区分”——2026-09-26

于是同一项按单交付的服务可以放在两个目标下看。周末赚一点现金也许合适，要靠它养团队就得重新算每单工时。

## 用你手头的材料开始

分析用你说话的语言，市场范围按业务实际覆盖的地方来定。默认在对话里给 Markdown。想并排比较几个点子时，可以要 CSV 或工作簿。第一次试用，给一段话就够了。
